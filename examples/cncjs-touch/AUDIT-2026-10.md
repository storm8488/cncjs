# Audit 2026-10: 31 work items

An audit-and-fix pass over the touch interface, its server services and the
packaging, run on 2026-10-29/30 on branch `feat/audit-31`. Nothing in this pass was
run on a CNC machine or on the Surface RT. Every figure below comes from a
development PC (Windows 11, Node.js 24.20.0, Chrome 156 headless through the
DevTools protocol), from fake controllers in Jest, from the Grbl JavaScript
simulator behind a real installed CNCjs, or from the offline browser fixtures.
"Hardware validation pending" means exactly that: the code exists and passes its
offline and simulator tests, and its behaviour on a machine is unknown.

## Base (A2)

The work starts from `feat/touch-settings-extras` at `b023616f`, not from
`integration`. Both branches fork from `master` at `dfad798e`. `git diff extras
integration` shows that `integration` adds nothing `extras` lacks: its 30 commits
carry the same fixes, without the pendant features (rapid overrides, screen lock,
automatic follow-up, Resume/Unlock in the strip) and without the depth and 3D
views. The six fixes A2 names are all in `extras`: Stop during dwells and homing
(`b869a3fb`), Grbl answers counted for the plate probe and the spindle restart

`08b6a23f`), resume after a board restart (`b1843d2d`), Pause/Stop during the
network fallback (`ae5cd8dd`, `da13b8e9`). There was nothing to reconcile.

State of the base, measured before any change: `verify-project.cjs` 73/73;
`jest src/server/services/touch src/server/api` 9 suites, 163/163, with "A worker
process has failed to exit gracefully".

## How the work was organised

One coordinator, one shared worktree, and one agent per group of items, each owning
an explicit list of files (server, files and API, quality, distribution, UI,
services, machine, client services, client machine, performance, projects,
maintenance, visualizer, layout). Agents did not commit; the coordinator committed
each lot. Each fix came with a test that fails on the previous code and passes
after; reports state the failing run.

Sensitive lots were then given to a separate agent whose job was to refute them,
on a frozen commit, with its own tests (`xv*-*` files, later folded into the
regular suites and deleted). Functional changes were frozen at `33b32db9` for the
final round; its fixes were made in a separate worktree (`feat/audit-31-fixes`),
re-verified there, then fast-forwarded into `feat/audit-31`.

## Limits

- No machine, no tablet. Chrome on the PC is about 25 times faster than the Surface
  RT for Suivi during a job; even with 4× CPU throttling, the relative gains are
  indications, not tablet figures. The CSS used (`inert`, grids, soft hyphens) is
  documented for Chromium 106 and not checked on the device.
- Coded server refusals (51 codes) are translated on the tablet; refusals without a
  code, and preview notes outside the pattern table, stay French in English and
  Spanish.
- Known limits left open:
  - the tablet that pilots a port cannot run its own sensitive host command (see A3);
  - project sheets: the last write wins between two devices;
  - `$13` is read from CNCjs's cached settings (see F1);
  - `autolevel:saveToFile` / `autolevel:loadFromFile` in the CNCjs Grbl controller
    accept any path from a Socket.IO client (CNCjs code older than this work; no
    touch client uses them);
  - `yarn lint` is too long a command line on Windows;
  - after a stream loss, the stream takes about 30 s to reconnect (`job-stream.js`);
    Pause and Arrêter stay available and the state is read over HTTP every 2 s;
  - `scripts/build-dev.ps1` does not copy the touch pages (`yarn win-dev` relies on
    the checkout); `api/custom/health` does not report the server's build commit.
